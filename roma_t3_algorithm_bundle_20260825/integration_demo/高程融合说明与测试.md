# 轻量高程融合：使用与验证

日期：2026-09-15。修改、备份、部署和 Orin 测试输出均位于 `/home/yanfa/P3` 内。

## 生效方式

实时与历史演示的**下一次新启动**默认使用 `variance`：方差加权高程融合 + 异常观测判断。此次不重启正在运行的任务，不播放 bag，不发车辆控制指令。当前已经运行的 Python 进程仍使用旧代码。

平时继续使用原启动命令即可；必须先将已有车辆停车并正常停止旧任务，才能新启动：

```bash
/home/yanfa/P3/start_live_mapping.sh 192.168.10.22
```

对比旧方式时，只在启动命令前加环境变量；不会更改原始 bag 或旧地图：

```bash
T3_ELEVATION_FUSION=mean /home/yanfa/P3/start_live_mapping.sh 192.168.10.22
T3_ELEVATION_FUSION=mean /home/yanfa/P3/start_history_mapping.sh --frames 12 --keep-view
```

显式指定新方式：把 `mean` 改成 `variance`。上面是两种数据源的独立示例，不要同时运行。直接调用演示 ROS launch 也可传 `elevation_fusion_mode:=mean`。通用算法入口保留原默认 `mean`；只将演示入口默认改为 `variance`。

模式和噪声参数在启动时读取，不支持运行中用 `ros2 param set` 热切换。启动日志会打印 `Grid elevation fusion: variance`；LiDAR 高程提交日志增加 `height_gate_rejected`，表示本次因历史高度门限而拒绝的样本数，不包括帧内 MAD 剔除。

## 改了什么

- 先保留原有帧内 MAD 去异常处理；LiDAR 仍按视觉位姿和原外参配准，再取 XY 单格中位数。
- 每个格子/批次作为一次相关观测，不因同一帧点密集就给它无限大的权重。
- 与历史高度一致时，按旧估计方差和新观测方差融合；新观测越可信，权重越大。
- 明显不一致时，保持该格的高度、融合置信度、有效观测数和高度统计不变。正常的小修正仍可逐步更新。
- 融合方差有下限和小的过程噪声，避免运行久了完全无法更新。只处理本次命中的格子，不额外扫描整张地图、不做射线清理。

**没有改定位、快速转弯处理、三维体素点云存储、RViz 配置、地图消息类型、格子尺度或坐标系。** 高程门限只保护高程层，不改变语义/占据更新，也不删改三维点云里的点。

## 初始参数和边界

参数在 `t3_semantic_mapping/elevation_fusion.py` 集中定义，并由节点声明为 ROS 参数。以下数值是保守起始设置，不是实际测得的传感器协方差；本版未传播视觉位姿、距离、入射角或外参不确定度。

| ROS 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `elevation_measurement_variance` | 0.04 m² | 双目单格观测噪声下限，相当于 0.20 m 标准差 |
| `elevation_lidar_measurement_variance` | 0.01 m² | LiDAR 单格观测噪声下限，相当于 0.10 m 标准差 |
| `elevation_process_variance` | 0.0001 m² | 每次该格观测的预测增量；拒绝时不累计到状态，不按空闲时间增长 |
| `elevation_min_variance` | 0.0004 m² | 后验置信度下限，防止过度自信 |
| `elevation_gate_sigma` | 3.0 | 历史一致性判断的标准差倍数 |
| `elevation_gate_min_m` | 0.30 m | 判断阈值的米制下限，避免细小高度变化被过度拒绝 |

批次观测方差 `R = 基础噪声 + 帧内有效样本高度方差`；高度差超过 `max(0.30 m, 3 × sqrt(P预测 + R))` 时拒绝，否则按 `K = P预测 / (P预测 + R)` 更新。帧内方差不除以点数，防止相关点导致虚假的高置信度。

限制：第一帧无历史可比，仍可能初始化错误；持续的真实地形变化也可能被门限拒绝。本版没有动态物体清除、遮挡推理或持续异常后自动换面机制。一个 XY 格仍只有一个高程，不能表达桥上/桥下等多层表面，也不能修复错误位姿导致的地图错位。真实序列精度仍需后续正常行驶验证。

原 `elevation_variance` 和 `roughness` 保持“已接受样本的高度离散程度”语义，与新融合置信度分开；对外不增加必选层。SQLite、NPZ 和 GridMap 导出的 `elevation` 已使用融合结果。

## 内存和地图兼容

新方式增加两个 float32 内部数组，每个格子共 8 字节；256×256 格的一块瓦片增加 **0.5 MiB**。写时复制的更新候选对被改动瓦片还会临时增加同等空间。旧 `mean` 模式不分配这两个数组。总开销仍随已分配瓦片数增长，不代表无限范围建图已经有固定内存上限。

内部可恢复快照：新方式写 v2，保存融合均值与置信度；原 v1 快照仍可读取并继续使用原均值模式，不伪造新置信度。旧版程序不能恢复 v2 内部快照；对外 SQLite/NPZ/ROS 接口结构不变。已有地图不会自动转换或重新融合，想比较两种方法需以后从同一数据、空地图分别生成。

## Orin 验证结果

环境：Orin，Linux 5.15.148-tegra，Python 3.10.12。没有运行 bag、视觉模型或新 ROS 节点；ROS 消息和 launch 参数测试只构造对象，不发布或启动算法。

新增 18 项测试通过，覆盖融合公式、异常拒绝、样本密度、噪声参数、置信度下限、写时复制、v1/v2 快照与恢复后续更新、损坏状态检测、输出字段及 launch 开关。另有原地图相关 92 项单元测试和独立 grid core 冒烟检查通过。原环境有 NumPy/SciPy 版本提示，本次未改系统依赖。

固定随机种子、完全相同输入、12,000 个 LiDAR XY 单格观测/次、4 个瓦片、每种方式计时 12 次，交替执行；包含瓦片事务复制和高程更新，不含定位、数采、显示或保存压缩：

| 指标 | 旧 `mean` | 新 `variance` |
| --- | --- | --- |
| 单次耗时中位数 | 610.9 ms | 667.7 ms |
| 单次耗时 P95 | 616.0 ms | 678.0 ms |

该测试增加约 **56.9 ms / 次（9.3%）**，不是整套算法变慢 9.3%。4 个瓦片的常驻滤波数组增加 2 MiB；这不是整机 RSS 增量实测。合成数据含约 1% 的孤立 ±2 m 异常，新门限在计时段拒绝 1,502 个观测；这不是实际 UE 地图精度结论。
