# FAST-LIO2 指标测试报告（2026-08-20）

> 文档性质：历史测试报告，不是2026-08-21当前运行手册。当前 `t5_ouster_fastlio.yaml` 仍配置 `imu_init_duration_s: 10.0`；而本报告完整轨迹已经证明该配置约245.8秒后严重发散。因此，在重新A/B验证并冻结参数前，FAST-LIO2只能作为实验入口，不能按本报告宣称已经具备可靠长时间定位能力。

## 1. 测试数据与方法

- 数据集：`/home/yanfa/SaveImages_Move_soft/rosbag_20260818_174206/bag`
- 传感器数据：4370 帧 Ouster 点云、43800 条 Ouster IMU
- 参考数据：2192 条 PQ 位姿
- 数据时长：438.48 s
- FAST-LIO2 有效输出：4354 帧，437.13 s
- 回放倍率：2.0（压力测试）
- 独立 ROS 域：40
- 点云输入坐标系：`sensor_frame`
- FAST-LIO2 输出坐标系：`camera_init -> body`

Ouster 使用内部时钟，PQ 使用系统时钟。评测前用 bag 中点云的记录时间和
Header 时间拟合线性时钟变换。拟合残差绝对值 P95 为 23.27 ms，最大值为
72.23 ms。

## 2. 外参问题与 A/B 修正

修正前正式配置使用：

```yaml
extrinsic_R: [-1, 0, 0, 0, -1, 0, 0, 0, 1]
extrinsic_T: [0.002441, 0.009725, 0.030662]
```

该变换适用于 Ouster 原生 LiDAR 坐标。但 bag 中点云已经由驱动转换到
`sensor_frame`，IMU 的轴方向也与 `sensor_frame` 一致，继续使用上述旋转会
重复转换。A/B 测试采用：

```yaml
extrinsic_R: [1, 0, 0, 0, 1, 0, 0, 0, 1]
extrinsic_T: [0.002441, 0.009725, -0.007533]
```

该修正已于 2026-08-20 写入正式配置
`src/t3_semantic_mapping/config/t5_ouster_fastlio.yaml`。

## 3. IMU 初始化修正

原 FAST-LIO2 以 `MAX_INI_COUNT=10` 判断初始化完成。该计数实际按 IMU 样本
递增，不是按秒递增；Ouster IMU 约 100 Hz，因此原初始化仅约 0.1 s。

现已增加 `mapping.imu_init_duration_s` 参数，正式配置设为 `10.0`。短回放实测
初始化累计 `10.0005 s / 987` 个 IMU 样本，估计陀螺零偏为：

```text
[0.00810833, 0.000318445, 0.000877412] rad/s
```

初始化后的短段输出为 9.55 Hz，点云至里程计延迟平均 29.59 ms、P95 31.02 ms，
仍远低于 2 s。与原约 0.1 s 初始化结果在相同 4.40 s、43 帧区间进行诊断性
对比：

| 短段指标 | 原约 0.1 s 初始化 | 新 10 s 初始化 | 变化 |
|---|---:|---:|---:|
| 固定尺度 SE(3) 位置 RMSE | 0.02496 m | 0.01771 m | 改善 29.0% |
| 位置误差 P95 | 0.04409 m | 0.02885 m | 改善 34.6% |
| 单帧位移 P95 | 0.02795 m | 0.02291 m | 改善 18.0% |
| 偏航稳定度（最有利符号关系） | 0.48055 °/s | 0.36071 °/s | 改善 24.9% |
| 高度跨度 | 0.01277 m | 0.04377 m | 变差 |

该短段结果说明延长初始化有利于平面位置和偏航，但高度问题尚未解决。旧结果来自
2 倍回放、新结果来自 1 倍回放，且区间较短，因此不能代替同回放倍率的完整轨迹
A/B 测试，也不能据此判定正式精度或稳定度达标。

随后完成了节点先启动、从 bag 第一帧开始、1 倍回放的完整轨迹验证。该次收到
4369/4370 帧点云，输出 4254 帧位姿，输出频率 9.94 Hz，延迟 P95 为 34.51 ms，
因此不存在足以解释精度结果的输入缺失或处理积压。初始化零偏与开头静止段离线
统计一致，但轨迹仍在约 245.8 s 后失锁：

| 完整轨迹诊断 | 原约 0.1 s 初始化 | 新 10 s 初始化 |
|---|---:|---:|
| 前 235 s 固定尺度 SE(3) RMSE | 1.688 m | 3.151 m |
| 相同 427.83 s 区间 RMSE | 2.906 m | 33074.051 m |
| 完整轨迹高度跨度 | 1.989 m | 129040.640 m |

10 s 结果已经发生公里级发散，完整 RMSE 不再具有正常定位误差含义。由此确认：
不能通过单纯延长 FAST-LIO2 整体初始化阶段来利用长时间零偏统计。该做法同时
改变了重力、零偏、初始协方差和首批参与建图的 LiDAR 数据，长轨迹稳定性反而
下降。正式配置应恢复短初始化；若继续利用静止零偏，应将预先统计的陀螺零偏
作为独立初值注入，并单独进行 A/B 测试。

## 4. 指标结果

| 指标 | 要求 | 本次结果 | 判定 |
|---|---:|---:|---|
| 定姿稳定度（偏航累计误差变化量/总时间） | < 0.005 °/s | 最有利符号关系下 1.831 °/s | 不满足 |
| 定位精度 | 优于 1%D | D=21.24 m，门限=0.212 m；固定尺度 SE(3) RMSE=2.852 m | 不满足 |
| 位姿确定处理时间 | ≤ 2 s | 中位数 16.81 ms，P95 22.47 ms，最大 41.61 ms | 满足 |
| 地图构建范围 | ≥ 0.5 km² | 当前实测已知区域 77.63 m² | 未完成范围验证 |
| 地图更新时间 | ≤ 2 s | 地图阶段 P95 0.316 s、最大 1.581 s；整帧 P95 1.983 s、最大 4.593 s | 地图阶段满足；整帧非全帧满足 |
| 轻量级地图存储量 | ≤ 3 GB/km² | SQLite 外推约 1.214 GB/km²；NPZ 外推约 2.053 GB/km² | 小范围样本满足 |

地图更新时间和存储量来自此前 0.1 m 分辨率的完整 Move-soft 建图结果；当前
默认值已改为 0.2 m，理论存储量会下降，但仍需重新进行完整联机测试。

## 6. 精度与稳定度说明

定位误差即使允许诊断性的 Sim(3) 尺度对齐，RMSE 仍为 1.101 m，大于
0.212 m 门限，因此当前运动精度确实未达到要求，不是单纯世界坐标初值不同。

偏航稳定度使用输出约 10 Hz 的全部有效位姿，计算相邻偏航误差变化绝对值之和
除以有效总时间。PQ 与 WIT IMU 两套参考在同一采样时刻下自身已经产生约
0.502 °/s 的同口径变化率，因此本次定姿稳定度不能作为正式验收值；但
FAST-LIO2 的最有利结果 1.831 °/s 仍明显高于 0.005 °/s。

## 7. 结论

当前FAST-LIO2的单帧实时性能充足，2倍数据速率下仍远低于2秒要求；Ouster点云坐标系重复变换问题也已经修正。但当前配置中的10秒整体初始化在完整轨迹上发生严重发散，所以“处理快”不能推导为“定位可用”。运动定位精度和偏航稳定度均未满足要求。下一步必须把静止零偏初值与整体初始化时长分开做完整A/B，检查点云去畸变及滤波参数，并使用可靠统一真值重新验收；完成前不得把FAST-LIO2列为生产主定位源。
