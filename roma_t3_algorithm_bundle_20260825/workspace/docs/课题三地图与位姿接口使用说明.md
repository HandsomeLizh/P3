# 课题三地图与位姿接口使用说明

> 更新日期：2026-08-21。当前对外坐标链为 `map -> odom -> base_link`；早期直接发布左相机光心的说明已经废止。

本文说明其他课题如何在 Orin 运行过程中获取课题三输出的当前完整地图、实时局部地图和位姿。

## 1. 接口总览

| 数据 | 接口或路径 | 类型 | 主要用途 |
|---|---|---|---|
| 正式实时位姿 | `/Car/T3/localization/odometry` | `nav_msgs/msg/Odometry` | 获取 `odom -> base_link` 位姿和速度 |
| 实时局部地图 | `/Car/T3/mapping/grid_map` | `grid_map_msgs/msg/GridMap` | 实时规划、避障和局部高精度显示 |
| 实时完整高程地图 | `/Car/T3/mapping/global_grid_map` | `grid_map_msgs/msg/GridMap` | 获取当前完整全局高程；地图版本变化时发布 |
| 完整全局总览 | `/Car/T3/mapping/global_overview` | `nav_msgs/msg/OccupancyGrid` | RViz 和低分辨率全局态势显示 |
| 离线完整高精度地图 | `<output_dir>/global_grid_map.sqlite3` | SQLite 文件 | 保存、交付和离线读取完整地图 |
| 直接矩阵完整地图 | `<output_dir>/global_grid_map.npz` | NumPy NPZ 文件 | 默认实车模式生成；大范围模式关闭 |

系统有两种全局输出模式：

| 模式 | 启动参数 | 完整全局GridMap | NPZ | SQLite | 局部图和总览 |
|---|---|---:|---:|---:|---:|
| 实车实时可视化 | 默认，或 `--full-map` | 开 | 开 | 开 | 开 |
| 大范围仿真 | `--lite-map` | 关 | 关 | 开 | 开 |

大范围模式只关闭按完整外接矩形展开的两项稠密产品，内部0.2 m稀疏全局地图和SQLite完整图层仍然持续更新。
| 完整地图版本 | `/Car/T3/mapping/global_map_revision` | `std_msgs/msg/UInt64` | 通知数据库已完整提交新版本 |
| 区域查询（辅助） | `/Car/T3/mapping/get_grid_map` | `grid_map_msgs/srv/GetGridMap` | 只需要某个局部区域时使用 |
| 强制保存 | `/Car/T3/mapping/save_grid_map` | `std_srvs/srv/Trigger` | 强制落盘并生成无损重建快照 |
| 特征匹配图（调试） | `/Car/T2/feature_matching/visualization` | `sensor_msgs/msg/Image` | RViz 查看双目和时间匹配结果；仅有订阅者时生成 |

默认运行目录下的完整地图路径为：

```text
/home/yanfa/P3/output/<运行目录>/global_grid_map.sqlite3
```

如果启动时设置了 `output_dir`，则文件位于：

```text
<output_dir>/global_grid_map.sqlite3
<output_dir>/global_grid_map.npz
```

## 2. 获取实时位姿

### 2.1 订阅位姿

```bash
ros2 topic echo /Car/T3/localization/odometry nav_msgs/msg/Odometry
```

只查看一帧：

```bash
ros2 topic echo --once /Car/T3/localization/odometry nav_msgs/msg/Odometry
```

检查实际输出频率：

```bash
ros2 topic hz /Car/T3/localization/odometry
```

### 2.2 位姿字段含义

```text
header.stamp                 对应本次处理图像的传感器时间戳
header.frame_id              连续局部里程计坐标系 odom
child_frame_id               ROS车体坐标系 base_link
pose.pose.position           base_link 原点在 odom 中的位置，单位 m
pose.pose.orientation        base_link 到 odom 的四元数，顺序 x、y、z、w
twist.twist.linear           child_frame 中的线速度，单位 m/s
twist.twist.angular          child_frame 中的角速度，单位 rad/s
pose.covariance              位姿协方差，ROS 标准 6x6 顺序
twist.covariance             速度协方差，ROS 标准 6x6 顺序
```

当前默认坐标关系为：

```text
map -> odom -> base_link
```

RoMa内部仍估计RGB10左相机光心，但当前T5 launch已经使用最新固定外参把结果转换为ROS `base_link`（前—左—上）后发布。原始标定车体系为前—右—下，程序在固定变换中同时完成物理外参和FRD到FLU约定转换。

默认同时发布对应 TF，可检查：

```bash
ros2 run tf2_ros tf2_echo map odom
ros2 run tf2_ros tf2_echo odom base_link
```

调试轨迹话题为：

```text
/Car/T3/debug/trajectory
nav_msgs/msg/Path
```

该话题用于RViz显示 `map` 中的累计车体轨迹，正式实时定位接口使用 `/Car/T3/localization/odometry`。

## 3. 获取运行中的完整高精度地图

### 3.1 直接订阅完整 GridMap

```text
/Car/T3/mapping/global_grid_map
grid_map_msgs/msg/GridMap
```

该话题将内部稀疏块拼接为一条标准 `GridMap` 消息，覆盖当前已分配块的完整矩形边界。地图版本发生变化时发布一次，不随每个图像帧重复发布；QoS 为 `RELIABLE + TRANSIENT_LOCAL + depth=1`，因此后启动的订阅者也能立即收到最近一版完整地图。

查看一版完整地图：

```bash
ros2 topic echo --once /Car/T3/mapping/global_grid_map grid_map_msgs/msg/GridMap
```

默认只发布高程图层，以减小实时 DDS 消息：

```text
elevation
```

消息中的 `info.resolution`、`info.length_x`、`info.length_y` 和 `info.pose` 给出当前全局栅格几何；`data[]` 中每个元素对应 `layers[]` 中的一个图层。未知栅格保留为 `NaN` 或相应未知值。

一次历史小范围实测中，4个内部块组成 `102.4 m x 102.4 m`、`0.2 m/cell`、`512 x 512` 栅格，单个 `elevation` 图层数据约 `1.0 MiB`；这只是样例，不是固定地图大小。地图继续拓展时，完整稠密消息会随包围矩形面积增大，因此大范围长期运行应使用 `--lite-map`，保留第4节的局部图和总览图。占据、语义、粗糙度等完整图层继续保存到SQLite，不因关闭GridMap和NPZ而丢失。

### 3.2 离线文件与版本通知

SQLite 是完整地图的保存与离线交付格式，不再是运行时获取完整地图的唯一方式。检查已完成落盘的地图版本：

```bash
ros2 topic echo /Car/T3/mapping/global_map_revision std_msgs/msg/UInt64
```

`global_map_revision=N` 表示数据库中的第 `N` 版地图已经完整提交。

默认实车模式中，`global_grid_map.npz` 由独立后台线程随地图版本更新。定位、建图和 ROS 发布线程不等待 NPZ 压缩；如果磁盘写入落后，后台线程合并中间版本并保存最新版本。调用保存服务或正常退出时会等待当前最新版写完。大范围模式不启动该NPZ线程。

直接读取完整矩阵：

```python
import numpy as np

with np.load("global_grid_map.npz", allow_pickle=False) as grid:
    print("frame:", grid["frame_id"].item())
    print("revision:", int(grid["map_revision"]))
    print("resolution:", float(grid["resolution"]))
    print("origin:", float(grid["origin_x"]), float(grid["origin_y"]))
    occupancy = grid["occupancy"]
    semantic_id = grid["semantic_id"]
    elevation = grid["elevation"]
    roughness = grid["roughness"]
    color_bgr = grid["color_bgr"]
```

二维图层使用 `[row, column]` 索引；`row=0` 对应 `origin_y`，`column=0` 对应 `origin_x`，行列分别沿地图的正 Y、正 X 方向增加。`occupancy=-1` 表示未知，其他值为 `0～100`。

### 3.3 Python 离线只读示例

```python
import io
import json
import sqlite3
import zlib

import numpy as np

map_path = "/home/yanfa/P3/output/roma_YYYYMMDD_HHMMSS/global_grid_map.sqlite3"

connection = sqlite3.connect(f"file:{map_path}?mode=ro", uri=True)
connection.execute("PRAGMA query_only=ON")
connection.execute("BEGIN")

metadata = {
    key: json.loads(value)
    for key, value in connection.execute(
        "SELECT key, value FROM metadata"
    )
}

tiles = []
for tile_x, tile_y, revision, elevation_offset_m, payload in connection.execute(
    "SELECT tile_x, tile_y, revision, elevation_offset_m, payload "
    "FROM tiles ORDER BY tile_y, tile_x"
):
    with np.load(
        io.BytesIO(zlib.decompress(payload)), allow_pickle=False
    ) as archive:
        layers = {name: archive[name].copy() for name in archive.files}
    tiles.append(
        {
            "tile_x": tile_x,
            "tile_y": tile_y,
            "revision": revision,
            "elevation_offset_m": elevation_offset_m,
            "layers": layers,
        }
    )

connection.commit()
connection.close()

print("map revision:", metadata["map_revision"])
print("map frame:", metadata["frame_id"])
print("resolution:", metadata["resolution"])
print("tile count:", len(tiles))
```

上述一次事务读取到的所有 `tiles` 合起来就是该版本的完整高精度地图。地图运行时可能同时存在 `-wal` 和 `-shm` 文件，因此应使用 SQLite 接口直接打开主文件，不要在程序运行过程中只复制主文件。

### 3.4 块坐标与地图坐标

每个块默认包含 `256 x 256` 个栅格。设：

```text
r  = metadata["resolution"]
L  = metadata["tile_length"]
x0 = metadata["origin_x"]
y0 = metadata["origin_y"]
```

块 `(tile_x, tile_y)` 左下角的地图坐标为：

```text
tile_origin_x = x0 + tile_x * L
tile_origin_y = y0 + tile_y * L
```

块内第 `row` 行、第 `column` 列栅格中心为：

```text
x = tile_origin_x + (column + 0.5) * r
y = tile_origin_y + (row + 0.5) * r
```

负数 `tile_x` 或 `tile_y` 是正常情况，表示地图位于全局原点的负方向。

### 3.5 离线完整地图图层

| 图层 | SQLite 内编码 | 解码含义 |
|---|---|---|
| `occupancy` | `int8` | `-1` 未知，`0~100` 占据概率 |
| `semantic` | `uint8` | 语义类别编号 |
| `semantic_confidence` | `uint8` | 除以 `255` 得到 `0~1` 置信度 |
| `elevation` | `int16` | `elevation_offset_m + value * 0.01 m`；`-32768` 未知 |
| `elevation_variance` | `uint16` | `value * 0.0001 m^2`；`65535` 未知 |
| `height_range` | `uint16` | `value * 0.001 m`；`65535` 未知 |
| `roughness` | `uint16` | `value * 0.001 m`；`65535` 未知 |
| `observation_count` | `uint16` | 栅格累计观测次数，最大值饱和 |

## 4. 实时局部地图与全局显示

### 4.1 实时局部地图

```text
/Car/T3/mapping/grid_map
grid_map_msgs/msg/GridMap
```

默认配置：

```text
范围：以车辆为中心滚动的 64 m x 64 m（320 x 320 个栅格）
分辨率：0.2 m/cell
图层：occupancy、semantic_id、elevation、roughness
QoS：RELIABLE + TRANSIENT_LOCAL + depth=1
```

该地图适合实时规划、避障和局部可视化，数据大小不会随总行驶距离增长。

### 4.2 完整全局总览

```text
/Car/T3/mapping/global_overview
nav_msgs/msg/OccupancyGrid
```

默认分辨率为 `1.0 m/cell`，地图发生变化时每 `20 s` 最多发布一次。它覆盖当前完整全局范围，但只包含低分辨率占据信息，适合超大范围全局态势显示。默认实车模式可订阅 `/Car/T3/mapping/global_grid_map` 获取完整高程；大范围模式则读取SQLite或按区域调用查询服务，避免持续传输完整外接矩形。

## 5. 位姿与地图联合使用

当前坐标分工为：

```text
Odometry.header.frame_id      = odom
Odometry.child_frame_id       = base_link
Local GridMap.header.frame_id = odom
Path.header.frame_id          = map
GlobalGridMap.header.frame_id = map
GlobalOverview.header.frame_id = map
SQLite/NPZ frame_id            = map
```

在局部GridMap中使用Odometry位置时二者都位于 `odom`，可以直接查询。要把实时车辆位姿画到全局GridMap、全局总览或SQLite/NPZ地图上，必须先通过 `/tf` 的 `map -> odom` 将 `T_odom_base_link` 转换为 `T_map_base_link`，不能直接把Odometry的 `(x,y)` 当成全局地图坐标。

推荐的下游处理流程为：

1. 持续订阅 `/Car/T3/localization/odometry` 获取 `odom -> base_link` 实时位姿；旧程序可继续使用兼容话题。
2. 订阅 `/Car/T3/mapping/global_grid_map`，收到消息后整体替换本课题缓存的完整地图。
3. 查询 `/tf` 中的 `map -> odom`，组合得到车辆在 `map` 中的位姿后再查询全局栅格。
4. 小范围实时规划可同时订阅 `/Car/T3/mapping/grid_map`，超大范围显示可使用 `/Car/T3/mapping/global_overview`。
5. 需要离线复现或交付时读取 `global_grid_map.sqlite3`。

## 6. 区域查询（可选）

只需要某个区域时，可以调用：

```text
/Car/T3/mapping/get_grid_map
grid_map_msgs/srv/GetGridMap
```

示例：

```bash
ros2 service call /Car/T3/mapping/get_grid_map \
  grid_map_msgs/srv/GetGridMap \
  "{frame_id: map, position_x: 0.0, position_y: 0.0, length_x: 30.0, length_y: 30.0, layers: [occupancy, semantic_id, elevation]}"
```

当前默认最多返回 `1,000,000` 个栅格。其他课题明确需要完整地图时，直接订阅第 3 节的 `/Car/T3/mapping/global_grid_map`，不需要依赖该区域查询服务。

## 7. 查看特征匹配结果（调试）

```text
/Car/T2/feature_matching/visualization
sensor_msgs/msg/Image
```

该图上半部分显示当前左、右图的双目匹配，下半部分显示关键帧与当前左图的时间匹配；绿色为时间匹配内点，红色为外点。发布器只有检测到订阅者时才生成调试图，不会额外执行 RoMa 推理。

当前T5 launch默认不创建该发布器。使用 `run_t5_roma_vo.sh --feature-matches` 可显式开启；开启发布器本身不等于持续渲染，仍需存在订阅者。

默认启动 RViz 时不订阅该图，以免产生不需要的调试渲染。需要查看时使用：

```bash
./scripts/run_rviz.sh --feature-matches
```

普通地图与轨迹可视化仍使用：

```bash
./scripts/run_rviz.sh
```

```bash
ros2 run rqt_image_view rqt_image_view /Car/T2/feature_matching/visualization
```

## 8. 强制保存与离线交付

运行过程中强制保存：

```bash
ros2 service call /Car/T3/mapping/save_grid_map std_srvs/srv/Trigger "{}"
```

该操作会：

- 等待当前完整 SQLite 地图写到最新版本；
- 保存无损重建快照到 `<output_dir>/_internal/grid_map_snapshot/map_index.yaml`；
- 保留当前交付文件 `<output_dir>/global_grid_map.sqlite3`。
- 默认实车模式等待完整矩阵文件 `<output_dir>/global_grid_map.npz` 写到当前地图版本；大范围模式没有该文件。

SQLite 文件用于其他课题读取最终图层；无损快照保留融合内部状态，用于后续重建或继续融合。
