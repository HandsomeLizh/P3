## 3. 实时仿真：按这个顺序操作

### 第一步：启动数采和建图

```bash
/home/yanfa/P3/start_live_mapping.sh 192.168.10.22
```

等待模型加载和启动完成。首次加载需要一些时间，不要因为几秒没有画面就重复执行。

该命令启动双目数采、视觉定位、LiDAR/栅格建图、指标网页及 Orin 屏幕上的“定位与建图”窗口。每次新建图任务使用独立结果目录，从空地图开始，不自动加载上次地图。

默认约每 4 秒采集一批（0.25 Hz）；传输和算法处理还会带来延迟。因此定位数字、轨迹不是每秒几十次更新，地图也不保证每帧发布整图。

先看右侧双目图像是否出现、“最近更新”是否周期性刷新、坐标是否有数值。静止时轨迹很短、地图变化少是正常现象。

### 第二步：启动车辆通信和控制 GUI

确认旧 GUI 已归零并关闭后执行：

```bash
/home/yanfa/P3/start_live_control.sh 192.168.10.22
```

此时才接通车辆端口 `6668`，打开 P3 内的配套控制 GUI。它与地图显示窗口是两个不同用途的窗口：一个负责驾驶，一个负责看地图。

新控制 GUI 初始速度为零；程序不会自动选择路线或设置非零速度。确认 GUI 收到车辆遥测，再进行驾驶。

若提示已有 `/car/cmd_vel` 发布者，先检查旧 GUI、固定路线或其他控制器；不要绕过检查强行启动多个控制器。

### 第三步：低速直行、转弯

1. 点击“归零滑条”，确认速度和曲率均为零。
2. 保持“持续发布 cmd_vel (10Hz)”勾选。
3. 点击“自动驾驶”。这里仅表示接受速度/曲率指令，**不是自动选路或避障规划**。
4. 先将线速度设为 `0.03～0.05 m/s`，曲率为 `0`，观察直行。
5. 需要转弯时小幅调整曲率；正负值对应相反转向。先低速确认实际方向，不要一开始就拉到最大值。
6. 看 UE 车辆、GUI 遥测和右侧视觉坐标是否都在变化；全局视角下几米的移动可能不明显，可切到“车辆近景”。

GUI 当前线速度滑条范围是 `-0.1～0.1 m/s`，曲率范围是 `-2～2 1/m`。这些是控制指令，不等于已经验证的车辆实际速度。角速度指令由 `角速度 = 线速度 × 曲率` 得到，速度为零时不会仅靠曲率原地转向。

控制 GUI 中原有的目标点、`/map` 和 `/plan` 画布尚未接入本课题规划闭环；本次不用它们控制目标点导航。

### 第四步：停车，再停止程序

先点击“紧急停车”（会归零并切停车模式），或先归零滑条再点击“停车”；确认 UE 车停稳后执行：

```bash
/home/yanfa/P3/stop_demo.sh
```

等待地图保存和各服务退出，再查询：

```bash
python3 "$ROOT/integration_demo/live_demo.py" status
```

不要用关闭终端、关闭 RViz 或拔网线代替正常停车与退出。“停车”按钮只切控制模式，不会自动归零滑条；再次点击“自动驾驶”前应先归零，避免恢复旧速度。

## 4. 地图窗口怎么看、怎么操作

| 区域或控件 | 含义 / 操作 |
| --- | --- |
| 左侧三维地图 | LiDAR 经视觉位姿配准后的累计点云；左键拖动旋转，滚轮缩放，Shift＋左键拖动平移 |
| “全局视角” / “俯视全局” | 恢复整体观察，避免缩放或旋转后找不到地图 |
| “车辆近景” | 观察车附近的地图和轨迹细节 |
| “自动容纳完整地图” | 根据地图范围调整视野；频繁自动缩放影响观察时可取消勾选 |
| 右侧高程图 | 地图俯视图；滚轮缩放，左键拖动平移，“恢复全图”复位 |
| 橙色线 / 青色标记 | 视觉轨迹 / 车辆朝向；三维显示标记会抬高以避免被地面遮挡，正式位姿不抬高 |
| X、Y、Z、航向 | 算法地图坐标系中的定位信息，不是 UE 世界原点下的绝对坐标 |
| 双目缩略图 | 当前收到的左右相机图像 |
| 高程色带 | 蓝色低、青色居中、橙色高；以色条的米制数值为准，不是激光强度 |
| 色差增强 | 使用 5%～95% 色域增强高度对比，只改颜色，不改变点的位置或高度 |

### 网格尺度与显示点数

- “参考网格”默认 `10 m/格`，是辅助量尺；透视视角下屏幕上的间距会缩短。核对尺寸时用俯视图或右侧比例尺。
- 真正的高程地图单元为 `0.2 × 0.2 m`。右侧充分放大后才能分清小格子，不要把参考网格线当作地图单元边界。
- 完整三维地图使用 `0.2 m` 体素；ROS 点云预览最多 20 万点，窗口进一步使用约 `0.5 m` 体素、最多 5 万点显示。显示稀疏不代表保存文件只有这些点。
- 从空地图启动也可能很快出现较大范围：第一批 LiDAR 就能看到车周围较远位置。车不动时，单帧扫描线形成的环纹和远处空隙可能很明显，不代表加载了旧地图。
- 历史与实时使用同一套显示布局，不另加数据来源标识。判断来源请看你启动的入口和状态文件。

只关闭了实时地图窗口、算法仍运行时，可以重新打开显示，不重建地图：

```bash
/home/yanfa/P3/run_rviz.sh
```

只关闭了控制 GUI、实时算法仍运行时，确认没有其他控制器后，可重新执行 `start_live_control.sh 192.168.10.22`。如果整套算法已经停止，需要重新从实时建图第一步启动。

## 6. 地图和轨迹保存在哪里

项目根目录下，每次任务有自己的结果文件夹：

```text
output_demo/
  envx_YYYYMMDD_HHMMSS/     实时任务
  replay_YYYYMMDD_HHMMSS/   历史任务
```

用实时或历史 `status` 命令查看本次 `Output` 路径，不要凭文件夹名字猜哪个仍在写入。

| 文件 | 内容 |
| --- | --- |
| `trajectory_map.tum` | 视觉轨迹：时间戳、位置和四元数 |
| `global_grid_map.sqlite3` | 持久化全局栅格地图 |
| `global_grid_map.npz` | 全局栅格数组的导出快照 |
| `lidar_map.sqlite3` | 完整三维体素点云库 |
| `lidar_map.pcd` | 完整三维点云导出，不受 RViz 显示点数上限限制 |
| `lidar_map_status.json` | 体素数量、地图路径等状态 |
| `pose_processing_time.csv` | 定位处理耗时记录 |
| `map_update_time.csv` | 建图更新耗时记录 |
| `logs/` | 数采、算法、显示、GUI、车辆通信日志 |
| `history_progress.json` / `history_verification.json` | 历史回放的处理进度 / 验证报告，仅历史任务有 |

运行中部分文件是低频快照；需要交付或复制一份完整结果时，先正常停车、停止任务并等待保存完成，再复制整个结果文件夹。不要在运行中删除 SQLite 的 `-wal`、`-shm` 文件，也不要直接编辑数据库。

当前两个实时入口只保存建图结果，**不会自动录制原始 bag**。short/long 自动路线与录包入口仍保留，但按当前安排不需要执行；不要把它们当成普通的“启动建图”按钮。

## 7. 提供给后续模块的主要接口

实时订阅方使用通信域 10；历史回放使用 11，并注意回放时钟。不要将两套数据混用。

| 话题 | 消息类型 | 用途 |
| --- | --- | --- |
| `/T3/semantic/current_pose` | `nav_msgs/msg/Odometry` | 当前视觉定位，`odom → base_link` |
| `/T3/semantic/trajectory` | `nav_msgs/msg/Path` | `map` 坐标系下的视觉轨迹 |
| `/T3/semantic/incremental_map` | `t3_interfaces/msg/IncrementalSemanticMap` | 旧接口，当前为完整 64×64 m 滚动窗口，不是纯差分补丁 |
| `/T3/mapping/grid_map` | `grid_map_msgs/msg/GridMap` | 局部栅格 |
| `/T3/mapping/global_grid_map` | `grid_map_msgs/msg/GridMap` | 全局高程栅格，低频发布 |
| `/T3/mapping/lidar_incremental` | `sensor_msgs/msg/PointCloud2` | 已按视觉位姿配准的新点云观测，可能重复覆盖旧区域 |
| `/T3/mapping/lidar_map` | `sensor_msgs/msg/PointCloud2` | 累计三维地图预览，不是完整磁盘地图 |

兼容位姿别名 `/Car/T3/localization/odometry` 保留。地图长度单位为米，具体坐标系以消息 `header.frame_id` 和 TF 为准。`/car/pose` 是 UE 参考位姿，不是课题三定位结果，其原点也可能不同。

栅格与轨迹使用保留最新消息的 QoS（`RELIABLE / TRANSIENT_LOCAL`）；位姿和新 LiDAR 观测使用 `RELIABLE / VOLATILE`。完整字段、数组顺序和 QoS 深度详见项目内 `integration_demo/双流程运行与接口联调.md`。

有高程不等于该格子一定可通行。规划端还需检查坡度、台阶、障碍、未知区域及车体尺寸；目标点规划和避障闭环尚未接入。

## 8. 当前地图更新机制与验证边界

- 位姿由双目视觉估计；LiDAR 使用这份视觉位姿和外参进行配准，不参与当前这套定位解算。
- 栅格高程同时接受双目深度和 LiDAR。LiDAR 在每个 XY 格中取本帧高度中位数。2026-09-15 新增轻量方差加权融合和异常高度门限，实时/历史演示下次新启动默认使用；已有运行不热切换。`T3_ELEVATION_FUSION=mean` 可在启动时切回原观测数加权方式。
- 新融合保留原地图话题和层字段；`elevation_variance` / `roughness` 仍是已接受高度样本的离散程度，不能当作定位精度或融合置信度。融合置信度单独存入内部快照。初始噪声参数是经验值，不是传感器标定结论；详见 [高程融合说明与测试](高程融合说明与测试.md)。
- 三维点云按 0.2 m XYZ 体素去重：新体素加入，已有体素保留首次存入的点。目前没有自动优化所有旧点，也没有完整动态障碍清除机制。
- 当前未启用全局回环/后端位姿修正、课题二语义 Mask 或地图点选规划。不要把占位语义、已有高程或“自动驾驶”按钮当成这些功能已经完成。
- 2026-09-15 已修正 LiDAR 输入轴向与外参约定不一致。修正前生成的旧点云及含 LiDAR 的高程地图不会自动修好，需以后从空地图重新生成；原始 bag 本身未改变。
- 已完成短时实时控制、采集、定位、建图和显示联调；不代表转弯稳定性、全地图精度、长期内存增长或规划安全性全部验收通过。现阶段先验证当前地图质量，不迁移整套新建图框架。

最近实时联调结果目录：`output_demo/envx_20260915_204421/`，含 `live_interface_check.json` 和 `live_motion_screen.png`。接口报告验证的是消息与输出存在，不是绝对定位精度报告。

## 9. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| GUI 设置了速度，车和 RViz 都不动 | 是否执行第二步车辆通信；GUI 是否有遥测；是否切到自动驾驶并勾选持续发布 |
| UE 车在动，地图看起来不动 | 看右侧坐标和最近更新时间；等待几个约 4 秒的采样周期；切换车辆近景；检查算法/数采是否还运行 |
| 第一步显示 READY，却没有图像 | READY 不等于 UE 持续提供数据；检查数采进程与 `logs/capture.log`，确认 UE 场景/IP/6665 端口 |
| GUI 地图画布显示未接收 | 旧 GUI 的 `/map`、`/plan` 不等于本套地图接口；查看“定位与建图”窗口 |
| 左侧点云像环线、地图出现空隙 | 静止时可能只有少量不同视角的扫描；远处扫描更稀疏；先检查是否随车辆运动逐步补充 |
| 一启动就有很大地图 | 检查是否新任务；新任务的一次 LiDAR 扫描也能覆盖较大范围；仅重开窗口则保留当前任务地图 |
| 点云重叠、分层或突然错位 | 先停车，保留日志和截图；检查位姿跳变、时间同步及外参，不能仅靠改颜色或降采样解决 |
| 界面提示数据输入结束 | 对历史任务属于正常结束，可继续查看最终地图；不代表实时定位还在运行 |
| 关闭 GUI / 地图后仍占内存 | 后台服务可能仍在运行；先停车，再用本套停止命令收尾，不要误停别人的算法 |
| 启动提示 already running | 先用 status 查明已有任务；需要新空地图时先正常停止，不要重复启动 |
